# Контекст проекта «Созвон»

Состояние на **16 ноября 2026 года**, часовой пояс пользователя — **Europe/Moscow**. Версия приложения — **0.4.0**.

Этот файл собирает требования пользователя, историю решений, устройство проекта, состояние установки и результаты проверок. Он предназначен для продолжения разработки без перечитывания переписки. Это документация проекта, а не дословный журнал чата. Если код изменится, сведения о поведении и проверках ниже нужно обновить.

## 1. Задача пользователя

Приложение должно освобождать пользователя от ручного подключения и выхода из конференций. Пользователь задаёт постоянную ссылку, время входа и условия выхода. В нужное время конференция открывается и подключается автоматически, затем происходит выход:

- в назначенное время;
- при резком уменьшении числа участников;
- по первому из этих условий, если включены оба.

Первоначально поддерживалась вкладка Microsoft Teams в Chrome. Затем добавлено расписание входов и поддержка установленного Zoom для Windows.

Желаемый пользовательский сценарий — оставить включёнными компьютер и Chrome. Фактическая реализация дополнительно требует заранее настроенных аккаунтов/доступов; для Zoom нужен разблокированный рабочий стол. Требование полностью автономной работы ещё не подтверждено живыми конференциями.

## 2. Явные пожелания и согласованные решения

- Пользователь согласовал определение оттока по умолчанию: за последние **2 минуты** ушло не менее **30%** участников и не менее **3 человек**. Все пороги настраиваются.
- Добавлено подтверждение устойчивого оттока: по умолчанию ещё **30 секунд** до выхода. Восстановление числа участников выше порога отменяет отсчёт.
- Пользователь попросил автоматически подтверждать браузерное окно «Выйти», возникающее при закрытии вкладки Teams. Реализовано через Chrome Debugger API.
- По просьбе пользователя нижний предел поля «Подтверждать, сек.» снижен с 30 до **1 секунды**.
- По следующей просьбе нижний предел поля «За последние, сек.» снижен с 15 до **1 секунды**.
- Пользователь попросил увеличить особенно мелкий текст. Основной шрифт увеличен до 15 px, подписи и пояснения — преимущественно до 14 px, числовые поля — до 16 px.
- Пользователь попросил убрать «Настройку счётчика» из интерфейса. Поле CSS-селектора удалено из окна расширения. Внутренняя поддержка селектора осталась в коде; новые задания из интерфейса используют автоматическое распознавание.
- Пользователь попросил отображать логотип в расширениях Chrome и на панели. Добавлены PNG 16/32/48/128 px: тёмная стрелка ↘ на светло-зелёном фоне со скруглением.
- Пользователь выбрал **еженедельное** повторение как типичный сценарий. Оно является вариантом по умолчанию; доступны также разовый вход, ежедневный и по будням.
- Zoom первоначально обсуждался как будущая идея без реализации. **16 ноября пользователь отдельно попросил реализовать его**, после чего добавлена версия 0.4.

## 5. Расписание

Пользователь выбирает режим «Вход и выход по расписанию», сервис, название, ссылку, дату/время первого входа, повторение, необязательное гостевое имя и условия выхода.

Поддерживаются `once`, `daily`, `weekdays`, `weekly`. Следующая дата рассчитывается по локальному календарю компьютера. Для будней первый вход должен быть в рабочий день. При изменении часового пояса компьютера рекомендуется пересоздать задания.

Если задан выход по времени, сохраняется интервал `exitOffset = deadline - joinAt`. В каждом повторе время выхода равно времени соответствующего входа плюс этот интервал. Например, вход в 10:00 и выход в 11:30 повторяют интервал 90 минут.

Хранение:

- `chrome.storage.local.schedules` — сохранённые задания, ссылки, имя, повторение, ближайшая дата, конфигурация и результат последнего запуска.
- `chrome.storage.local.preferences` — последние настройки условий выхода.
- `chrome.storage.session.watch` — ручное наблюдение Teams.
- `chrome.storage.session['watch:' + scheduleId]` — отдельное наблюдение за запланированной конференцией.
- Текущие наблюдения переживают остановку/перезапуск service worker, но не полный перезапуск Chrome. Будущие задания сохраняются.

Основные поля задания: `id`, `provider`, `title`, `url`, `guestName`, `joinAt`, `nextAt`, `repeat`, `config`, `exitOffset`, `enabled`, `lastStatus`, `lastOccurrence`; для Zoom также используется подтверждение `zoomPrepared`.

Alarms:

- `sozvon-join:<id>` — ближайший вход по заданию.
- `sozvon-schedules` — резервная проверка расписания раз в 30 секунд.
- `sozvon-check` — резервная проверка наблюдений раз в 30 секунд.
- `sozvon-deadline` — дедлайн ручного наблюдения.
- `sozvon-deadline:watch:<id>` — дедлайн конкретного задания.

Перед открытием конференции событие **сначала помечается выполненным**, а следующая дата сохраняется. Это предотвращает дубли при перезапуске фонового процесса. Компромисс: авария между отметкой и открытием может привести к пропуску запуска; автоматическое повторение такого входа намеренно не делается вслепую.

Допустимое опоздание — **5 минут**. Более старые события пропускаются; повторное задание переносится на ближайшую будущую дату. Если время выхода уже прошло, запоздалый вход не выполняется.

Другие правила:

- До 100 сохранённых заданий.
- Одна и та же ссылка не добавляется повторно на то же ближайшее время, если задание уже включено.
- Предыдущий активный запуск того же задания не запускается повторно.
- Несколько конференций Teams могут работать независимо.
- Для Zoom допускается один управляемый запуск одновременно; Teams при этом работает независимо.
- Приостановка расписания затрагивает только будущие входы.
- Остановка автоматизации текущего запуска отменяет его автоматические действия/выход и оставляет конференцию открытой; будущие повторы сохраняются.
- Удаление задания также останавливает автоматизацию его текущего запуска, оставляя конференцию открытой.
- Редактирования сохранённого задания пока нет: удалить и добавить заново.

## 6. Условия выхода

Значения по умолчанию:

- `timed: false`;
- `drop: true`;
- `percent: 30`;
- `minimum: 3`;
- `windowSeconds: 120`;
- `graceSeconds: 30`.

Диапазоны:

- процент: 1–100;
- минимальное число ушедших: 1–10000;
- окно измерения: 1–3600 секунд;
- подтверждение: 1–300 секунд.

Должно быть включено хотя бы одно условие. Дата выхода должна быть в будущем; для расписания — позже входа.

Для оттока берётся максимум числа участников в скользящем окне. Текущее снижение должно одновременно удовлетворять процентному и абсолютному порогу. Когда это произошло, исходный максимум фиксируется на время подтверждения. Если число восстановилось выше порога, кандидат отменяется.

Отсутствующий, неоднозначный, нулевой, некорректный или устаревший счётчик не является числом «0». История/подтверждение сбрасываются. Перерыв между измерениями больше 20 секунд также нарушает непрерывность и сбрасывает историю.

Дедлайн по времени имеет приоритет и не ждёт подтверждения оттока.

Особенность коротких интервалов: интерфейс допускает 1 секунду по просьбе пользователя, но Teams опрашивается примерно раз в **5 секунд**, Zoom — примерно раз в **1 секунду**. Фоновые ограничения браузера и задержки UI Automation могут увеличить интервал. Очень короткое окно может не набрать достаточно измерений и вообще не обнаружить отток; точность до секунды не обещается.

## 7. Teams

Поддерживаемые HTTPS-домены: `teams.microsoft.com`, `teams.live.com`, `teams.cloud.microsoft`. Zoom-домены в браузерные host permissions не добавлялись.

### Вход

При запуске создаётся отдельная вкладка. До подтверждённого входа разрешаются переходы внутри Teams; при переходе на авторизацию расширение ждёт возврата и сообщает, что нужно войти вручную.

`joiner.js` работает с поддерживаемыми явными элементами и русскими/английскими подписями:

- выбор «Продолжить в браузере»;
- заполнение гостевого имени, если оно задано и поле пусто;
- выключение камеры и микрофона по известному состоянию переключателей;
- нажатие кнопки подключения только после подтверждения выключенных медиа;
- проверка входа по наличию кнопок конференции — roster и hangup;
- попытка открыть панель участников.

Кнопка входа может быть отключена до заполнения имени: это учтено и проверено тестом. Повторные нажатия ограничены интервалом 10 секунд.

Зал ожидания, авторизация и загрузка не считаются подключением. Неизвестное состояние камеры/микрофона останавливает нажатие кнопки входа и показывается пользователю. Через 15 минут неподтверждённого входа автоматизация Teams останавливается, оставляя вкладку для проверки. Если заданный выход наступил раньше, предпринимается закрытие вкладки Teams.

### Счётчик

`reader.js` читает явные счётчики и заголовки количества находящихся в звонке. Он исключает приглашённых, зал ожидания, скрытые и расходящиеся значения. Видеоплитки и строки списка не пересчитываются: интерфейс может быть виртуализированным.

Распознавание не универсально: Microsoft меняет разметку. Iframe и закрытые Shadow DOM текущим читателем не поддерживаются. При недоступном счётчике выход по времени работает независимо.

### Выход и браузерное подтверждение

Обычный content script не может нажать кнопку в системном окне Chrome. Поэтому `close-tab.js`:

1. Проверяет целевую вкладку.
2. Временно подключает `chrome.debugger` только к ней.
3. Включает домен `Page` и повторно проверяет URL.
4. Вызывает `Page.close`.
5. На `Page.javascriptDialogOpening` с типом **beforeunload** отправляет `Page.handleJavaScriptDialog` с `accept: true`.
6. Ждёт фактическое событие удаления вкладки, затем снимает подключение и обработчики.

Другие вкладки и обычные `alert`/`confirm` не подтверждаются. Через 12 секунд без фактического закрытия фиксируется ошибка. Открытые DevTools и другие подключения отладки могут мешать. Chrome может временно показывать полосу отладки.

После подтверждённого подключения изменение URL отключает наблюдение, чтобы не закрыть другую страницу. Это консервативное поведение может остановить автоматизацию при нормальной внутренней навигации Teams.

## 8. Zoom для Windows

### Схема работы

Расширение использует `chrome.runtime.connectNative('com.sozvon.zoom')`. Оно отвечает за расписание и передаёт параметры запуска. C#-помощник отвечает за установленный клиент Zoom, частые измерения и условия выхода.

Команды помощника: `PING`, `START`, `STATUS`, `STOP`, `LEAVE`. Ответы имеют `type: reply`, `requestId`, `ok`; обновления состояния — `type: status` и `state`. Корреляция запросов защищает от принятия чужого ответа за текущий. Ожидание ответа в расширении ограничено 20 секундами.

Состояния помощника: `idle`, `joining`, `watching`, `leaving`, `done`. Каждый запуск имеет отдельный UUID `runId`. Отмена/выход должны соответствовать текущему `runId`; запоздалые статусы не активируют остановленное наблюдение.

Протокол stdin/stdout: длина JSON в первых 4 байтах little-endian, затем UTF-8 JSON. Вход ограничен 65536 байтами, выход — менее 1 MB. Диагностические строки не выводятся в stdout, чтобы не испортить протокол.

### Ссылки и запуск

Принимаются HTTPS-приглашения на `zoom.us`, `zoom.com` и их поддоменах с путём `/j/<числовой ID 9–11 цифр>`. Из ссылки берётся токен `pwd`; имя пользователя добавляется отдельно. Логины в URL, неподходящие домены, произвольные схемы, `/my/`, `/w/` и слишком длинные значения отвергаются.

Помощник ищет установленный `Zoom.exe` в App Paths, зарегистрированном обработчике Zoom и стандартных каталогах. Он не исполняет произвольную команду из реестра: извлекается только путь к Zoom.exe. Запускается exe с одним реконструированным аргументом `--url="zoommtg://…/join?..."`; параметры кодируются, shell не используется.

Это адаптер к установленному приложению, а не Zoom Meeting SDK. Схема запуска и дерево UI Automation зависят от версии клиента; их совместимость в живой конференции пока не подтверждена.

### Окна, счётчик и выход

Перед запуском помощник проверяет доступность рабочего стола и отказывается входить при распознанной уже идущей конференции. Он запоминает существовавшие окна и выбирает только новое подходящее окно Zoom. Привязка включает HWND, PID, время запуска процесса и UI Automation RuntimeId.

Это защита от управления старым/другим окном, но она имеет компромисс: если Zoom переиспользует старое окно, вход может остаться нераспознанным. Не следует вручную открывать другую конференцию Zoom во время автоматического подключения.

Счётчик читается из явной подписи «Participants (N)» / «Участники (N)» или единственного явного числа внутри соответствующего элемента управления. Панели в отдельных окнах читаются только при связи владения с привязанным окном того же процесса. Подсчёт списка имён и видеоплиток не используется.

При необходимости помощник пытается открыть панель участников. При недоступном счётчике правило оттока не срабатывает, но дедлайн сохраняется.

При выходе выбираются только распознанные кнопки Leave/Выйти. Отдельный диалог подтверждения должен принадлежать управляемому окну. Нажатие End/Завершить для всех и принудительное завершение процесса не используются. Результат подтверждается исчезновением привязанного окна либо явным сообщением о завершении; одно нажатие кнопки успехом не считается. Через 30 секунд без подтверждения показывается ошибка.

Из распознанного зала ожидания помощник пытается выйти при дедлайне или после 15 минут неподтверждённого входа. Нераспознанные окна не закрываются вслепую.

### Медиа, авторизация и отмена

Перед созданием задания пользователь должен подтвердить, что в самом Zoom настроен вход с выключенными камерой и микрофоном. Приложение не меняет эти настройки автоматически: Zoom может подключить медиа до появления доступных кнопок. После входа помощник дополнительно нажимает известные действия выключения, но не переключает неизвестное состояние.

Вход в аккаунт, MFA, CAPTCHA, запросы доступа и ручной код конференции не автоматизируются. Зал ожидания требует допуска организатора. Имя передаётся в ссылке, но конкретные формы клиента могут потребовать ручного участия.

После команды STOP конференция остаётся открытой. При обрыве Native Messaging помощник заканчивает работу и оставляет конференцию для ручной проверки; расширение останавливает автоматизацию. Уже идущий звонок не подхватывается автоматически после перезапуска Chrome. Будущие задания при этом сохраняются.

## 9. Разрешения и данные

Разрешения расширения:

- `storage` — локальное расписание и состояние;
- `alarms` — запуски и дедлайны;
- `scripting` — подключение скриптов к уже открытым вкладкам Teams;
- `debugger` — подтверждение системного окна выхода из вкладки;
- `nativeMessaging` — связь с локальным помощником Zoom.

Разрешения на сайты ограничены тремя доменами Teams. Zoom управляется локально, а не через DOM сайта.

Расписание, ссылки и заданное гостевое имя хранятся локально. Помощник держит параметры текущего запуска в памяти. Ссылки и имя передаются соответствующему сервису при подключении. Отдельный сервер, служба Windows, сетевой порт и планировщик Windows не создаются. Журнал переписки, имён других участников, аудио и видео не ведётся.

В этот контекст не включены реальные ссылки конференций, пароли, токены `pwd` и учётные данные пользователя.

## 13. Приоритеты дальнейшей работы

1. Обновить расширение до 0.4.0 в Chrome и проверить соединение кнопкой «Проверить помощник Zoom».
2. Подтвердить подготовку аккаунтов и медиа-настроек самим пользователем.
3. Провести испытание на отдельной тестовой конференции Teams: вход, определение реального подключения, счётчик, дедлайн и системное подтверждение.
4. Аналогично проверить Zoom: запуск по полной ссылке, новое окно, состояния ожидания/подключения, счётчик, выход участника и принадлежность диалога подтверждения.
5. Если распознавание не сработает, адаптировать селекторы/подписи по фактически наблюдаемому интерфейсу. Не возвращать технический CSS-селектор в пользовательский интерфейс без нового запроса.
6. Проверить недельный повтор, закрытый popup, поздний запуск Chrome и отмену текущей автоматизации отдельно от паузы расписания.
7. При необходимости добавить редактирование заданий и улучшить восстановление текущих сеансов. Сейчас это не реализовано и не должно предполагаться.

В этой переписке пользователь не передавал настоящую постоянную ссылку, дату конкретного будущего запуска или данные аккаунта. Новые реальные задания за него не создавались.
